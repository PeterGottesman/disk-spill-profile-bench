How scale and memory limits change TPC-H performance

All 22 queries ran twice at seven scale factors under three host capacities on an NVIDIA GB300. Query runtime comes from DuckDB’s timer; structured Quent traces attribute each batch’s moves into HOST and DISK to a query. This report compares the second iteration of each condition.

Measured relationship

With 196 GiB of HOST capacity, the 22-query warm-time sum grows from 6.677 s at SF100 to 74.488 s at SF1000. HOST placements first appear at SF500; this configuration records no DISK placements through SF1000.

At SF500, the 1 GiB cap sends Q3 to DISK, but total runtime is only 1.9% above the 196 GiB run. At SF750, 8 GiB spills two queries to DISK and total runtime rises 39.5%; 1 GiB spills three and rises 48.4%. At SF1000, four queries spill at 8 GiB and five at 1 GiB, raising total runtime 65.6% and 89.4%, respectively. The first-iteration SF1000 sums show the same ordering: 80.450 s, 124.624 s, and 141.969 s at 196, 8, and 1 GiB.

Where the extra time goes

At SF1000 with 1 GiB HOST, Q5 alone rises from 6.345 s to 39.281 s (6.19×), contributing 32.936 s, or 49.5%, of the workload’s added time. The five disk-spilling queries have a median 2.65× runtime ratio; the other 17 have a median 1.00× ratio.

How to interpret the measurements

HOST placement means a batch’s tier changed from GPU to HOST. DISK placement means a change from GPU or HOST to DISK. Quent’s batch capacity_bytes is the logical batch size at that transition; it does not measure compressed disk traffic or storage writes. Disk-input task counts come from task Preparing.origin_tier containing DISK. The analyzer links each placement to its query through the pipeline plan.

This is one machine, one run per condition, two sequential iterations, and a fixed query order. Runtime differences smaller than a few percent should be treated as noise or cache effects. The host cap controls the spill path; it does not isolate spill cost from other scheduling and memory effects. Sirius printed a thread-local-storage panic on process shutdown after writing complete results, but each benchmark process exited successfully.
